RTL ownership and schedule
Core alone owns S40 xd_state, xq_state, du_d_state, du_q_state and sat_state.
Inputs plus OLD five-tuple capture once at acceptance N. Stateless evaluator
accepts N+1, emits N+17, core captures N+18. Limiter accepts N+20, emits N+180,
core captures N+181; private result pads 75 further clocks. The response at
N+256 commits all five values atomically on OK only. Each accepted transaction
has one completion slot, including invalid bus, range, command-reset and faults.
Pre-edge ready is low on completion; earliest next acceptance is N+257.
Input ready is reset_n && !busy. Counter advances only while pending.
Captured/candidate data have no asynchronous reset and are masked by resettable
busy/result/error control; DSP-friendly child arithmetic remains unchanged.
The sole normal persistent write site is inside successful +256 completion.
All debug names/types are frozen response-aligned hierarchical registers; no
extra top pins, KEEP/DONT_TOUCH, run-time gains or new arithmetic are introduced.

Missing launches/responses, wrong-time engine pulses or missing private result
produce INTERNAL_ERROR at the same +256 slot. A wrong-time pulse ON +256 is
included in the current commit condition, rather than only a delayed error flag.
Invalid bus is signed-checked at capture with priority over command reset.
Every error zeros visible voltages/flags and raw/hi/scale debug, preserves the
full persistent state, and exposes captured OLD values in OLD and NEXT debug.
Hardware reset clears persistent state, visible/debug values and control
asynchronously and aborts pending children. Functional/debug values otherwise
hold between completed responses; only output_valid pulses.
