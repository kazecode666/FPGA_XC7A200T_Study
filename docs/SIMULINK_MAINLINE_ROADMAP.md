# Simulink 主导的 FPGA 电机控制主线

更新：2026-10-21。依据：用户在 StudyL1 完成后明确的项目方向，以及本仓库 `main@319ee0103c4f4b42752fad49014ead2cfbefceea` 的远端资料初查。

本文定义后续目标和阶段关系，不表示这些阶段已经实施，也不授权一次执行全部阶段。当前执行范围只有 [M0](../coordination/tasks/m0_simulink_model_asset_audit.md)。

## 1. 目标与非目标

主要目标是学习并建立一条可复现的模型到硬件流程：以 Simulink 研究和维护电机控制算法，先得到浮点闭环参考，再建立面向硬件的定点控制器模型，由 HDL Coder 生成算法 HDL，利用 Vivado 检查资源、结构和时序，回到闭环环境验证实现影响，最终与真实控制器运行管理和板级接口集成。

当前以电流环 PI-FOC 为首个主线算法范围候选，实际源路径、有效模式及边界由 M0 核实。完整 MIL 中其他控制算法可以作为后续研究分支，不要求首次 HDL 化时全部迁移。

非目标：长期维护浮点 Simulink / HDL Coder / 手写 SV 三套并行算法；把所有旧 RTL 强制包装成新架构；把整个带电机对象的 MIL 顶层直接生成 HDL；立即追求全部功能或产品级基础设施；本轮实机部署。

## 2. 模型职责：不是简单二选一

| 对象 | 后续职责 | 不能直接作出的推断 |
|---|---|---|
| `PMLSM_ThreeLoop_Simple.slx` | 保留当前核心算法修正、可视化和联合仿真成果，作为快速算法/闭环回归环境 | 名称 Simple 不等于没有限幅、复位或模式逻辑，也不等于足以实机运行 |
| `PMLSM_MIL_ControlCore_Sim.slx` | 系统级仿真组织、完整启动/命令/反馈/日志功能的参考 | 名称完整不证明安全功能齐全或当前默认工况适合新主线 |
| `PMLSM_ControlCore_Block.slx` | 完整 MIL 中算法与运行逻辑的来源之一，必须与顶层一起审计 | 不默认与 Simple / DSP 同步，不默认 HDL 兼容 |
| `PMSLM_Close_Loop_MBDL4.slx` | DSP 实机运行行为、参数、标定、保护和外设集成的参考 | TI 外设模块不能当作 FPGA 已具备的接口实现 |
| 未来浮点参考 / 定点 HDL 控制器 | 同一控制需求下的数值参考与硬件实现源 | 目前尚未由本任务创建，文件名和最终分层在审计后确定 |

建议保留 Simple 和完整 MIL 各自的测试用途，并逐步复用同一控制器核心、参数来源和场景定义。不是把三份旧模型强行合并成一个大 SLX，也不是整套复制后各自修改。

发生模型差异时，先核对控制语义、参数和证据，再决定采用哪一实现；不以文件更大、时间更新或曾经用于 DSP 作为正确性依据。

## 3. 必须分清的边界

### 算法与实现

浮点参考用于控制性能研究；定点模型明确位宽、范围、舍入、饱和、内部状态和采样语义。定点作为当前优先路线，特殊模块采用浮点需要给出资源/时序/精度取舍，不把“FPGA 必须定点”作为前提。

电流 FOC 的候选边界包含反馈变换、dq PI、已有前馈/解耦、限幅、反变换和 SVPWM；最终是否全部进入同一 DUT，由实际模型审计和阶段设计决定。PWM 载波、影子更新、互补输出、死区和故障封锁单独明确职责，不能把 SVPWM 算法输出直接当成经过实机验证的门极信号。

### 控制器与仿真环境

启动/命令中分开真实运行逻辑与测试激励；反馈中分开测量处理与仿真理想量；电机、负载、平均逆变器、场景注入和仿真日志不作为完整硬件 DUT 一起转换。

定义共同输入输出时必须记录单位、范围、采样时刻、使能/复位、有效性和参数更新行为。物理单位接口可与板级原始码/寄存器接口分层，不提前锁死为旧手写 RTL 的位宽。

### 实机行为与板级接口

使能/停机、启动状态、模式切换、限幅、故障和参数更新行为在模型设计阶段就梳理，不等算法验收结束才定义。具体 ADC/编码器/通信/驱动板接口沿用已经提供的硬件方案；先核查材料与接口映射，不重新选型或猜测协议。

目前 Simple 中理想速度/角度与实际传感器处理的差别须记录。算法基线可暂保留现状；真实反馈链路接入阶段再显式加入其测量、计算和滤波延迟，不借本轮整理顺便重整定速度环。

## 4. 后续阶段与退出条件

| 阶段 | 主要工作 | 交付 / 退出条件 |
|---|---|---|
| **M0：当前任务** | 三模型功能审计、参数来源、硬件/工程资料盘点与缺项补齐 | 有证据的差异表、资产/依赖清单、未决项及 M1 建议；完成后停在 PR Review |
| M1：浮点基线与模型边界 | 选定实际 PI-FOC 来源，区分算法、运行管理、板级适配与 plant；明确共同工况及误差口径 | 可复现纯 Simulink 基线、控制器接口与功能恢复清单；必要变更有对照 |
| M2：定点 HDL 实现模型 | 按需要另建定点控制器，落实内部运算/状态类型、限幅、复位和采样语义 | 数据类型表、浮点/定点误差与边界工况报告，HDL 可实现性检查 |
| M3：生成与 RTL 功能验证 | 从定点模型生成 HDL，验证输入输出、状态、使能、复位和延迟关系 | 与相应实现参考对齐的 RTL 结果、可复现生成配置与报告；不是只看曲线相似 |
| M4：硬件实现与闭环验证 | Vivado 资源、综合/布局布线时序；生成 RTL 接入共享闭环环境 | 满足约定时限与资源要求，真实计算/采样/PWM 延迟进入闭环，影响范围回归通过 |
| M5：完整控制器集成 | 按前期已定义的行为逐项接回指令、参数、运行状态、保护和实际反馈处理，集成板级接口 | 完整顶层与关键正常/异常场景验证；控制器功能与接口责任明确 |
| M6：分阶段上板 | I/O 与安全关断先验，随后在用户另行批准的条件下进行功率级和电机实验 | 独立实机方案及结果；不能由仿真通过自动推定可安全上电 |

M3/M4 是迭代关系：流水线、位宽或调度有变化，回到模型/生成配置并重做受影响验证。M5 不是“到最后才考虑保护”；它是把 M0/M1 已梳理的实机行为逐项落实和集成。

每阶段只完成其直接目标，不自动进入下一阶段。当前任务不包含 M1—M6 的实施授权。

## 5. 验证关系

| 比较 | 验证目的 |
|---|---|
| 浮点参考 vs 定点实现模型 | 量化、饱和和内部状态改变是否满足控制性能要求，不要求浮点与定点每个数相同 |
| 定点实现参考 vs 生成 RTL | 相同复位、使能、有效样本和对齐规则下检查实现一致性；启用优化时明确生成模型及延迟映射 |
| 生成 RTL 闭环 vs 浮点/定点闭环 | 保留实际实现延迟与更新时刻，检查控制动态；不能为使曲线重合而删除闭环真实延迟 |
| 板级接口测试 vs 实际外设协议 | 数据采集、有效性、超时、跨时钟与 I/O 时序，不由算法输入数字测试代替 |
| 完整顶层 vs 实机需求 | 启停、异常、参数更新、故障封锁和反馈失效，不能只沿用独立 FOC 的通过结论 |

不预先把旧 RTL 当作新模型的唯一 golden reference。新模型的数学/数值语义有变化时，旧参考向量只能用于其仍适用的部分，差异必须解释。

旧 Step 7 使用 active CMP 连接平均逆变器、避免重复 PWM 延迟和死区的经验继续参考；具体 `2500`、位宽、延迟数值和测试阈值属于旧实现，不未经审计固化到新主线。

## 6. 旧成果保留与复用原则

`PWM_Controller/`、`PWM_Breathe/`、`Motor_PWM/`、`FOC_*/`、`motor_control_ip/`、StudyL1、脚本及报告保持原位。复用其工具链经验、测试场景、时序认识、接口实验与已验证的数学知识；不直接继承未复核的生产实现责任。

以后确需复用某个旧 PWM/接口模块，应单独记录复用范围、接口语义和新顶层验证。不能为了证明学习成果有价值而强制把新生成 FOC 接到旧调度器，也不要求所有外设都必须由 HDL Coder 生成。
