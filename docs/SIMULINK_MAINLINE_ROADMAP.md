# Simulink 主导的 FPGA 电机控制主线

更新：2026-10-23。PR44 的 M0 审计已合并至 `main@2e10c2d`；用户确认另存纯 Simulink PI-FOC 浮点模型、统一电机/调制/控制时基、外部 `.m` 加载工作区。

**PR45 的 [M1A 设计](../coordination/specs/m1a_pure_simulink_float_baseline_design.md)已合并，当前阶段为 [M1A 实施任务](../coordination/tasks/m1a_pure_simulink_float_baseline.md)及[分步计划](superpowers/plans/2026-10-23-m1a-pi-foc-float-baseline.md) Review。** 本次没有创建新模型或执行仿真。M1 拆成独立浮点基线与运行管理两个检查点，避免同时改变过多行为。旧 M0 报告保留其当时状态，不重复执行已经接受的审计。

## 1. 目标与非目标

以 Simulink 研究和维护控制算法，得到浮点闭环参考，再建立面向硬件的定点控制器模型；由 HDL Coder 生成算法 HDL，利用 Vivado 检查资源和时序，回到共享闭环环境验证实现影响，最后接入真实控制器行为和板级接口。

首个算法来源明确为 `PMLSM_ThreeLoop_Simple/Control_Task_10kHz/FOC_Algorithm` 的 PI-FOC。完整 MIL 中的 DPCC/DPICC/PICDO 继续保留研究，不加入首轮迁移。旧手写 FOC/PWM 不作为正式实现必须沿用的底座。

不长期维护三套并行生产算法，不把带电机对象的整个 MIL 顶层生成 HDL，不把模型整理扩展成完整产品基础设施，也不由仿真通过推定可以安全上电。

## 2. 模型与参数职责

| 对象 | 职责 |
|---|---|
| 新 `PMLSM_PI_FOC_Float_Baseline.slx`（待实现） | 纯 Simulink 主线入口；唯一自由运动 plant、共享参数/场景、PI-FOC及必要外环；不依赖旧 backend/XSI |
| 新 `init_PMLSM_PI_FOC_Float_Baseline.m`（待实现） | 可读的默认参数/场景来源，加载 MATLAB 基础工作区；不另藏 Model Workspace/MAT 参数副本 |
| 旧 Simple | 算法修正、外环及 plant 来源与迁移对照；原文件保留 |
| 完整 MIL + ControlCore | 系统功能、启动、测量、保护和研究算法参照；原文件保留 |
| DSP 实机模型 | 已有运行管理和外设语义参考；TI 外设不能当作 FPGA 已实现接口 |
| 后续定点控制器模型 | 相同控制需求下的硬件实现源；不复制出另一套独立发展的电机/工况 |

新参数的单位、范围、来源、使能/复位和时基必须可追溯。同一电机参数被控制器与 plant 使用时来源一致；不以文件更大、更新或用于过 DSP 就认定正确。

## 3. 阶段与退出条件

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| M0：已合并 | 三模型功能/参数审计、硬件/工程资料与缺项补齐 | PR44 已接受；动态与板级事项未冒充完成 |
| **M1A：当前实施准备** | 另存纯浮点模型，外部 `.m` 初始化，统一电机/调制/控制时基，移除旧 co-sim 依赖 | 新模型与参数入口入库，新进程真实运行、物理调制核对、源/新迁移对照和必要步长检查 |
| M1B：运行管理 | 在稳定浮点基线之上分步恢复启动/对齐、使能、故障锁存/恢复和适用的行程行为 | 各行为边界与代表性正常/异常场景通过，不与 M1A 一次混改 |
| M2：定点实现模型 | 独立控制器的位宽、范围、舍入/饱和、状态与采样语义，HDL 支持检查 | 数据类型表、浮点/定点误差及边界测试 |
| M3：生成与 RTL 功能验证 | HDL Coder 生成，与相应实现参考比较 | 状态/复位/使能/有效数据与延迟映射正确，可复现生成 |
| M4：实现与闭环验证 | Vivado 资源和布局布线时序；RTL 接入共享闭环环境 | 满足时限/资源，真实采样/计算/PWM延迟进入闭环 |
| M5：完整控制器集成 | 按前期定义接回指令、在线参数、实际测量处理、外设及保护 | 完整顶层和关键异常场景验证；不以独立算法通过代替集成 |
| M6：另行批准的上板 | 先 I/O 与安全关断，后受控功率级和电机实验 | 独立实机方案、授权与结果 |

M3/M4 可迭代；改流水线/位宽/调度后重做受影响验证。M1B 与 M5 的分工是先定义并建模运行行为、再接入真实硬件，不把安全设计全部拖到最后。

## 4. 新浮点基线的关键边界

FOC 包含变换、dq PI、前馈解耦、圆限幅、反变换和 SVPWM；PWM载波/影子更新/六路互补门极与板级关断另有职责。新浮点接口先定义为死区前、更新前的上管 command duty，不等同于实际 active duty 或门极。

电流100 us、速度1 ms、位置10 ms，PWM等效周期100 us；plant基准步长1 us。保留源半周期50 us更新延迟与单一平均死区责任，后续接入实际RTL时替换相应责任，不重复叠加。详细约定、默认物理参数和测试要求以 M1A 设计为准。

暂保留 Simple 的理想位置/速度/电角度反馈；实际采集、位置差分及滤波延迟纳入范围后再单独验证。仿真电机、负载、平均逆变器和日志不是最终完整 HDL DUT。

## 5. 验证关系与复用原则

| 比较/检查 | 目的 |
|---|---|
| 源纯 Simulink vs 新浮点模型 | 参数迁移和接口整理不静默改变算法；独立物理重构不能被曲线对照替代 |
| 浮点 vs 定点实现 | 衡量量化/状态/饱和对控制性能的影响，不要求逐数相等 |
| 定点实现参考 vs 生成 RTL | 相同复位、使能和有效样本下检查一致性，明确流水线/生成模型映射 |
| RTL闭环 vs 参考闭环 | 保留真实实现延迟，不为重合而删除延迟 |
| 板级接口 vs 外设协议 | 数据、时序、超时、CDC与I/O约束，不由算法输入数字代替 |
| 完整顶层 vs 实机需求 | 启停、异常、调参、故障封锁和反馈失效 |

旧 `2500`、位宽和延迟是旧 RTL 合同，不自动约束新生成设计。旧测试在参数/算法仍适用时复用；不全量重跑 Step6/7/StudyL1，也不让新浮点模型为匹配旧定点误差而改变算法。

所有 PWM/FOC 工程、RTL、学习文件和历史报告保持原位。确需复用某个接口模块时单独记录范围和新顶层验证。真实接口信息优先查已有资料，不重新泛问用户。
